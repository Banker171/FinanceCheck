# FinanceCheck

Личное приложение на русском языке для учета денег, выхода из долгов и накопления финансовой подушки. Windows-приложение для одного пользователя на Electron, React + TypeScript, Express и SQLite. Веб-режим сохранен для разработки. Для разработки из исходников нужен Node.js **24+** (используется встроенный `node:sqlite`); для готового `.exe` ничего дополнительно устанавливать не нужно.

## Windows: установка готового приложения

Откройте [Releases](https://github.com/Banker171/FinanceCheck/releases/latest) и скачайте:

- **FinanceCheck-0.4.0-x64-setup.exe** — установщик для Windows 10/11 x64 с выбором каталога и ярлыками.
- **FinanceCheck-0.4.0-x64-portable.exe** — один исполняемый файл для запуска без установки.

Node.js, Python, браузер, отдельный сервер и интернет для основных функций **не нужны**: интерфейс, движок, база SQLite и расчеты входят в приложение. Откройте файл и следуйте мастеру установки. Начальный профиль пустой; вымышленные данные доступны по кнопке «Посмотреть демо».

**С версии 0.4.0 обновления встроены в установленное Windows-приложение.** Один раз установите `setup.exe` поверх прежней версии. После этого при запуске (через 15 секунд) и каждые 6 часов программа проверяет новые стабильные релизы и автоматически скачивает обновление. В настройках есть «Обновления программы» с прогрессом и ручной проверкой; готовое обновление также видно в верхней части экрана. Нажмите «Установить и перезапустить» и подтвердите. Перед установкой создается резервная копия. Простое закрытие программы не устанавливает обновление. Для portable и запуска из исходников автоустановка отключена: чтобы получать обновления внутри программы, используйте установленную версию.

Проверка и загрузка требуют интернета, но не GitHub-токена или API-ключа. Обновления скачиваются целиком (ориентировочно 120 МБ), поэтому учитывайте расход трафика. При отсутствии сети программа продолжает работать. SHA512 проверяется библиотекой electron-updater; TLS и штатная проверка настроенного издателя не отключаются. Текущая сборка не подписана сертификатом издателя и доверяет HTTPS-источнику релизов и контрольным суммам из метаданных.

Данные сохраняются отдельно от программы, в `%APPDATA%/FinanceCheck/financecheck.sqlite` (папку можно открыть через меню «Файл → Папка данных»). Обновление приложения не перезаписывает профиль. Удаление программы по умолчанию сохраняет финансовые данные; удаление из интерфейса требует отдельного подтверждения. Переносимый файл также использует профиль Windows, а не папку рядом с exe. Скопировать только exe на другой компьютер недостаточно для переноса личных данных: скачайте JSON-экспорт и восстановите его в новой установке. Ключ ИИ на новом устройстве задается отдельно.

При обновлении **не удаляйте профиль и папку данных**. Закройте приложение и установите новую версию поверх прежней под той же учетной записью Windows. Перед сменой версии приложения или формата хранения автоматически сохраняется полный JSON-снимок в подпапку `backups`. Если создать копию не удалось, переход базы отменяется. Обычный перезапуск не запускает миграцию повторно. Эти копии находятся на том же диске: для защиты от поломки устройства храните отдельный экспорт вне него.

Переход с 0.2.0 сохраняет имя, остатки, подушку, долги, операции и ключ ИИ. Старый общий доход переносится **только в текущий месяц при первом запуске обновления**, без заполнения будущих месяцев. Исходные значения остаются в автоматической копии. См. [руководство по заполнению](docs/user-guide.md).

Внешний ИИ необязателен. В приложении откройте **Настройки → Подключение ИИ**, укажите собственный API-ключ и доступную вашему аккаунту модель. Ключ хранится через Windows DPAPI, не включается в установщик и не возвращается интерфейсу после сохранения. На экране аналитика отдельно разрешите отправку сводки. Без ключа доступен офлайн-разбор по правилам, а не обученная нейросеть. Запросы внешней модели требуют интернета и оплачиваются в аккаунте провайдера.

Текущая сборка не подписана коммерческим сертификатом издателя: Windows может показать предупреждение о неизвестном издателе. Для контроля целостности в релизе есть `SHA256SUMS.txt`; подпись и контрольная сумма — разные проверки. Не требуется отключать антивирус или системную защиту.

## Разработка и сборка Windows

Нужен Node.js 24+. На Windows:

```bash
npm ci
npm run check
npm run test:electron
npm run dist:win
```

Готовые файлы появятся в `release/`. На отдельном Windows CI-раннере `npm run test:upgrade` устанавливает настоящий релиз 0.2.0, заполняет тестовый профиль и обновляет его новым установщиком; проверяются история, остатки, зашифрованный ключ и автокопия. Этот тест изменяет тестовую установку и предназначен для одноразового CI-раннера, а не компьютера с личными данными. Для запуска из исходников: `npm run desktop`. На тегах и при ручном запуске workflow тест `npm run test:auto-update` дополнительно собирает временную следующую версию, проверяет отказ при поврежденной SHA512, отмену установки, обычное закрытие без обновления и настоящее автообновление с перезапуском. Тестовая следующая версия не публикуется. Оба теста установки разрешены только в Windows GitHub Actions и используют отдельный профиль. Сборка использует Electron 45 с встроенным Node.js 24 и NSIS. Рабочая база, `.env` и ключи исключены из пакета. Движок Electron включает свои лицензии в каталог приложения. Первичная загрузка Electron и сборочных инструментов требует сети.

В GitHub Actions есть сборка на **windows-latest** с проверкой настоящего Electron-приложения, сохранения между перезапусками и формированием `.exe`. Артефакт сборки доступен в Actions. Тег `v*` после успешной проверки автоматически публикует установщик, переносимый файл, блок-карту, `latest.yml` и SHA256 в Releases. Метаданные `latest.yml` обязательны для встроенного обновления; публикуется только стабильная проверенная сборка. Источник обновлений — `https://github.com/Banker171/FinanceCheck/releases/latest/download/`. Никакие токены в приложение не встраиваются. Подписание можно добавить отдельно при наличии сертификата; оно не имитируется.

В Linux-облачной среде загрузки требуют рабочего HTTPS-прокси и доступного каталога кеша. Используйте `NODE_USE_ENV_PROXY=1`, `electron_config_cache=/tmp/financecheck-electron-cache`, `ELECTRON_CACHE=/tmp/financecheck-electron-cache`, `ELECTRON_BUILDER_CACHE=/tmp/financecheck-builder-cache`, `XDG_CACHE_HOME=/tmp/financecheck-cache`. Не отключайте TLS или проверку контрольных сумм. Результат кросс-сборки не заменяет проверку запуска на Windows.

## Веб-режим для разработки

```bash
cd /workspace/FinanceCheck
npm ci --cache /tmp/financecheck-npm
npm run dev
```

Frontend работает на порту 5173, API — на 3001. Vite проксирует `/api` в Express. Данные сохраняются в `data/financecheck.sqlite` и переживают перезапуск. Начальный профиль пустой. Кнопка «Посмотреть демо» загружает вымышленные данные только в пустой профиль; реальные данные не перезаписываются.

Для собранной версии:

```bash
npm run build
npm start
```

Express обслуживает и интерфейс, и API на 3001. Сервер по умолчанию слушает только `127.0.0.1`. Это личная версия **без авторизации и разделения пользователей**: перед публикацией в интернете необходимы аутентификация, изоляция пользователей, HTTPS и защита резервных копий. Dev-сервер Vite доступен на интерфейсах среды; ограничьте к нему доступ средствами платформы. Подключение банков и реальные переводы не реализованы.

## Возможности

- Обзор остатков, доступной до дохода суммы, долгов и резерва.
- Доходы и расходы, категории, поиск, фильтр по месяцу, удаление операций.
- Долги: основной остаток, ставка, минимальный платеж, день платежа, редактирование и удаление.
- Платежи по долгам с отдельным указанием погашения основного долга из банковской выписки. Проценты тоже являются расходом, но не уменьшают основной долг.
- Календарь на текущий и следующий месяц. Незаписанные платежи после даты оплаты отмечаются как возможный пропуск, а не установленная банком просрочка.
- Подушка: фактически выделенная сумма, цель в месяцах необходимых расходов, дни покрытия.
- Три стратегии распределения свободных денег: 10%, 40% или 80% в подушку, остальное в досрочное погашение.
- Порядок погашения: высокая ставка первой («лавина») или маленький остаток первым («снежный ком»).
- Сценарии изменения доходов и расходов без изменения сохраненных данных.
- Локальный разбор по правилам и опциональный диалог с внешней моделью.
- Доходы по месяцам: независимые суммы, история и отдельное отображение фактических поступлений. Пустой месяц не считается нулевым и не наследует прошлую сумму.
- Экспорт и восстановление JSON с подтверждением. Перед восстановлением создается копия текущего состояния. Ключи модели не входят в экспорт и не заменяются импортом.

## Как считаются деньги

**Общий остаток = начальный остаток + внесенные доходы − внесенные расходы.** Начальный остаток указывается до внесенных операций. В него входит подушка. Изменение планового месячного дохода не создает фактическое поступление.

**Доступно до дохода = общий остаток − выделенная подушка − оставшиеся платежи по долгам до следующего дохода.** Из этой суммы еще нужно оплачивать повседневные расходы. Ориентир на день делит ее на число дней до следующей даты дохода. Отрицательный результат не скрывается. Если резерв превышает остаток, приложение предупреждает о несоответствии.

**Свободно по месячному плану = доход, указанный для этого месяца − необходимые расходы − минимальные платежи по долгам.** Доход задается в «Настройки → Доходы по месяцам», а реальные поступления добавляются как операции. План не прибавляется к остаткам денег. Это расчет полного месячного бюджета, а не гарантированный остаток сегодня; уже совершенные траты текущего месяца не вычитаются из месячного плана повторно. Текущий капитал не направляется автоматически на досрочное погашение.

Прогноз работает с целыми копейками. В начале каждого расчетного месяца на остаток долга начисляются проценты `остаток × годовая ставка / 12`, затем вносятся минимальные платежи и распределяется остаток бюджета. Выделенный резерв не приносит расчетных процентов. Если долгов больше нет, свободные деньги идут в подушку. Когда подушка достигла цели, свободные деньги направляются в долги. После достижения обеих целей остаток остается нераспределенным. При дефиците расчет не обещает дату погашения; горизонт ограничен 600 месяцами. Основной прогноз использует доход каждого заполненного месяца и останавливается на первом пропуске. В «А что, если…» отдельно можно рассчитать явно условный сценарий одинакового дохода на все будущие месяцы; он не меняет сохраненную историю.

Это приближение: не учтены ежедневное начисление процентов, комиссии, льготные периоды кредиток, штрафы, налоги и изменения ставок. Просроченная задолженность не моделируется отдельно; все долги предполагаются обслуживаемыми по указанному графику. Ставка — указанная пользователем годовая процентная ставка, не ПСК. Необходимые расходы не должны повторно включать платежи по долгам. Цель подушки считается от необходимых расходов без кредитных платежей. Для учета платежей как части резерва потребуется отдельное расширение модели.

Календарь поддерживает одну редактируемую ожидаемую дату на каждый заполненный месяц. Сумма события — доход месяца минус записанные поступления этого месяца, минимум ноль. Уже полученные деньги не планируются повторно. Если поступлений несколько, дата служит ориентиром для ближайшей оставшейся выплаты и обновляется вручную. Новый месяц без записи не получает ни сумму, ни дату от предыдущего. Если будущего дохода нет, приложение не придумывает дневной лимит: показывает остаток после платежей текущего месяца. Даты 29–31 при необходимости заменяются последним днем месяца. Календарные расчеты используют UTC, валюта — RUB. Оплата долга считается по операциям соответствующего месяца, а не по банковскому статусу; прошлые месяцы просрочек сверяются самостоятельно.

Платеж снижает основной долг только на указанную пользователем часть. Удаление платежа восстанавливает эту часть. Если остаток был вручную сверен с банком, старые платежи отмечаются как сверенные: их удаление уже не меняет новый остаток. Изменение названия, ставки или даты без изменения остатка не является сверкой. Удаление долга оставляет операции расходами, но снимает их связь с долгом.

## ИИ-аналитик

Без ключа работает **локальный разбор по правилам**. Он объясняет расчет, но не интерпретирует произвольные вопросы и не является нейросетью.

Для Windows используйте настройки внутри приложения. Для веб-режима скопируйте `.env.example` в `.env` и настройте на сервере:

```dotenv
FINANCECHECK_AI_KEY=<ключ провайдера, задается только на сервере>
FINANCECHECK_AI_MODEL=gpt-4.1-mini
```

Не вставляйте ключи в клиентский код, чат или Git. При использовании облачного прокси привяжите секрет `FINANCECHECK_AI_KEY` к HTTPS-хосту `api.openai.com` в настройках среды; имя и доступность модели зависят от аккаунта провайдера. После настройки перезапустите сервер. Для внешней модели требуется сетевой доступ к `api.openai.com`. Локальному режиму он не нужен.

Перед каждым запросом приложение проверяет согласие на отправку сводки. Без отмеченного согласия работает локальный разбор даже при настроенном ключе. Отправляются вопрос, агрегаты доходов/расходов, остатки, ставки, платежи, предупреждения и результаты сценариев. Имена пользователей и кредиторов, категории и комментарии операций не передаются. Сам вопрос передается целиком: не вводите в него лишние персональные данные. Ключ остается на сервере. История диалога хранится только в состоянии экрана и не передается модели; каждый запрос независим.

Приложение отправляет `store: false`; это не обещание нулевого хранения у провайдера — действуют условия вашего аккаунта. Есть ограничение одновременных запросов, таймаут и локальный разбор при ошибке. Модель не получает инструменты для денежных переводов. Ее рекомендации не применяются к данным автоматически. Числа и сроки в сводке рассчитаны программно; текст модели все равно требует проверки.

**Обучение модели здесь не выполнялось.** Личная финансовая история сама по себе не является обучающей выборкой: она описывает ситуацию, но не содержит проверенного правильного решения. См. [план развития модели](docs/ai-development.md). Для начала обучения нужны согласие на использование данных, качественные примеры, отдельная контрольная выборка и вычислительные ресурсы/доступ к сервису обучения. Наличие данных в приложении не заменяет эти требования.

## Проверки

```bash
npm run check       # расчеты, HTTP API, SQLite, TypeScript, production-сборка
npm run test:e2e    # реальные сценарии в Chromium; поднимает отдельный сервер
```

Браузерные тесты используют отдельную **in-memory** базу на порту 3101, не рабочие данные. Берется `/usr/bin/chromium`, если он установлен; можно задать `CHROMIUM_PATH`. Иначе установите браузер через `npx playwright install chromium`. В ограниченной облачной среде могут потребоваться дополнительные разрешенные домены для загрузки браузера. Тесты проверяют десктоп и мобильный экран, ввод профиля/долга/платежа, перезагрузку, демо, сценарии, аналитика и экспорт. API-тесты внешней модели используют имитацию провайдера и не подтверждают качество реальных ответов или рабочий ключ.

## Структура и настройки

- `desktop/` — отдельное окно приложения, защищенный локальный API, IPC и хранение ключа.
- `electron-builder.yml` — установщик NSIS и переносимый exe.
- `src/` — интерфейс и типы.
- `server/finance.mjs` — расчеты и локальный аналитик.
- `server/store.mjs` — SQLite и проверка входных данных.
- `server/app.mjs` — HTTP API и подключение внешней модели.
- `tests/` — автоматические проверки.

Сервер читает `.env` из рабочей директории; уже заданные переменные окружения имеют приоритет. Дополнительные переменные: `PORT` (3001), `HOST` (`127.0.0.1`), `FINANCECHECK_DB` (`data/financecheck.sqlite`). `:memory:` используется только для тестов. Файл SQLite не шифруется приложением; ограничьте права на каталог и доступ к хосту. Для резервного копирования используйте SQLite backup или остановите сервер перед копированием; не копируйте только основной файл при активном WAL. Удаление профиля не является гарантированным физическим стиранием SQLite, снимков среды и ранее созданных копий.
